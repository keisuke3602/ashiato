## 2026-11-05(木)
- ログ読み込み(Logpush、nginx/Apache)、AIの種類の判別、ページ別集計。
- Claudeに渡す「ブリーフ」、下書きの検証(根拠が無い・事実と合わない下書きは保存を拒否)。
- 日本語のレポート画面、調べた順番、ページ一覧、前後比較、アップロード画面。
- 例の下書きは、Claude Code の中の別の Claude に、ブリーフと指示文だけを渡して書かせた実出力。
  1回、事実と合わない転送の下書きを検証が拒否し、書き直させた。
- デモ台本と締切までの段取り(docs/demo.md)。

## 2026-11-06(金)
- 提出先の過去ギャラリーと受賞者の話を読み、概要文の方針を決める
  (「根拠が無ければ拒否する」と「公開リポジトリ」を前に出す)。
- API キーは Kei が用意する予定。それまでは Claude Code のアカウントで進める。

## 2026-11-07(土)
- Claude API(`claude-opus-5-5`)で、合成データの旅館から下書きを取る(15件、検証を通過。この日の最初の取得で、現在の例は、あとの取り直しの9件)。
- ログを入れるとその場で Claude が下書きを作る `--live`、承認した下書きのコピー(反映のしかた付き)、
  直したあとのログを別の欄から入れる前後比較。
- アクセスログが無い事業者のために、サイトの公開ページの診断(目2)と、AIの答えの確認(目3)を追加。
  目2は、合成データの旅館のサイトで、実際の API(`--live`)でも動いた(夜に確認)。目3は、偽のクライアントでのテストまで。
- Managed Agents を初めて実行(`ant apply` で Agent と Environment を作り、Session を1つ、上限3ドル)。
  合成データのブリーフで、下書き13件が、検証に1回で通った。当時は、例の下書き(`examples/ryokan/`)を、この出力に差し替えた(のちに、下の取り直しの9件に差し替え)。
- 検証の穴を埋める: ローカルのサーバーが、別のサイトからの要求と、内部アドレスへの取得を断るようにした(テストつき)。
  文書の数字と、仕込み7つへの判断を、データから確かめるテストを足した。
- 画面を、4ページ(ダッシュボード、調べた順番、次にやること、直したあとの変化)に分け、グラフを足した。
- 需要の読み取り: AIの要求に載っているURLを、需要の手がかりにする。AIが「あるはず」と想定して取りに来て、無かったアドレス(404)と、
  よく読まれているページ(200)をブリーフに入れ、Claudeが、探されたページと、続きの話題を提案する。
  提案には、探された記録か、元のページが要り、記録に根拠のない思いつきのページ提案は、コードが保存を拒否する。
  Claude API で取り直し(有効9件、拒否0件)。続きの話題の提案は2件。数字(◯回探した)は、Claudeではなく、コードがブリーフから出す。

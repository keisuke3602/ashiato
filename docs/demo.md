# デモ台本（3分、日本語）と締切までの段取り

審査: インパクト30 / デモ25 / Claudeの活用25 / 深さと実行力20。デモは動画1本で、事前録画。
設計メモ（docs/design.md）のデモの節を、画面と作業に結びつけて具体化したもの。

## 方針
- 冒頭は事業者の困りごとで始める。分析画面で始めない。
- 一番見せたいのは「AIが探したのに、ページがなかった」が数字で見え、下書きが出て、人が承認する流れ。
- 画面に出る旅館・サービスはすべて架空。画面の隅に「架空のサイト・合成データ」と出す。
- 「AIに聞くと旅館が出てこない」の場面で、実際のAIの回答を作って見せない（でっち上げになる）。
  文字のカードで困りごとを語る。
- 下書きはClaudeが実際に書いたものだけを見せる。見本の下書き（`ashiato/sample.py`）をClaudeの出力として見せない。

## 録画の注意
- ライブ実行は止まりうる。Claudeの実行は先に1回通して、成功した結果を保存し、画面はその結果で動かす。
  録画中に「Claudeが考えている」ように見せる場合も、保存した実際の出力を使い、そう分かる説明を概要に書く。
- 数字は画面の値をそのまま読む。ナレーションの「3割」は、実際の割合に合わせて直す。
- 実在の事業者名、実ログ、実際の集計値は画面に出さない。

## 今ある物と足りない物（2026-11-05）
- ある: ログの読み込み・分類・集計、ブリーフ、下書きの検証、データA/B、承認キューの画面（見本の下書きで動作）。
- 足りない: 読み込み画面、全体のページ一覧、エージェントの作業の表示、前後比較、そして**Claudeの実行そのもの**。
  Claudeの実行にはAPIキーが要る。キーが無いと「Claudeの活用」（25点）の中心が示せない。

# 足跡 (ashiato)

AIに見つけてもらうための道しるべ。

サイトのアクセスログには、AIが訪ねて来た足跡が残っています。
足跡は、AIが読みに来たページ、探したのに無かったページ、
AIの回答から来たお客さんを教えてくれます。
ところが、ログを読める人は、限られています。
足跡は、その足跡を読み取り、何を作り、何を直せばAIに見つけてもらえるかを、
日本語で、下書きつきで示します。

Built with Claude: Japan 2026 への参加作品です。

## 誰のためのものか

エンジニアもコンサルタントもいない、小さな事業者(宿、商店、自治体のサイト)。
ログを開いたことがない人でも、AIに見つけてもらえているかが分かるようにします。

## できること

AIがそのサイトをどう見ているかを、3つの目で確かめます。どれも、事実を集めるのはコード、判断と下書きはClaude、承認は人です。

1. **アクセスログ**: AIが実際に何を読みに来て、読めたか(主な機能。下の「使ってみる」)
2. **サイトの公開ページ**: AIが読める状態か。`robots.txt` で断っていないか、案内図(サイトマップ)にあるか、本文が短くないか。
   アクセスログが無くても使えます(`ashiato/sitecheck.py`)。
3. **AIの答え**: お客様が聞きそうな質問に、AIがどう答えるか。Claudeにウェブ検索をさせた結果で、他のAIの答えとは限りません
   (`ashiato/ask_ai.py`)。

機能の一覧:

- Cloudflare Logpush や nginx/Apache のアクセスログを読み込む(行頭にドメイン名が付く形式も読めます)
- AIクローラー、AI回答エンジン、人の訪問を見分ける
- AIが探したのにページが無かった箇所を見つける
- AIが探したURLと、よく読まれているページから、次に作るページを提案する(根拠つき。思いつきの提案は保存を拒否)
- Claudeが原因を判断し、直すための下書きを根拠の行つきで作る
- 人が承認して使う(自動では何も公開しない)
- 承認した下書きを、まとめてコピーできる(「反映のしかた」付き)
- 修正の前後で結果を比べる(直したあとのログを、あとから入れたときに出ます)

## 方針

- 実際のログはこのリポジトリに入れません。デモは合成データだけを使います。
- 下書きは提案です。公開するのは人です。

## 使ってみる

標準ライブラリだけで動きます(Python 3)。

```
python3 scripts/gen_synthetic.py            # 合成データA(旅館)を data/synthetic/ryokan/ に作る
python3 scripts/gen_synthetic_b.py          # 合成データB(読書ノートのサービス)を data/synthetic/readnote/ に作る
python3 scripts/serve.py data/synthetic/ryokan/site/before 雪待荘 \
  --response examples/ryokan/claude_response.json
pip install anthropic                       # API で下書きを取るときだけ必要（API キーは環境変数 ANTHROPIC_API_KEY。`.env.example` を `.env` にコピーして入れ、`set -a; source .env; set +a` で読み込む）
python3 scripts/run_advisor.py data/synthetic/ryokan/before.ndjson data/synthetic/ryokan/site/before 雪待荘 out/ryokan_response.json --run
```

`serve.py` は、2通りで起動できます。
- `--response`(上の例): 保存済みの返答を使います。API は呼ばず、キーも要りません。
- `--live`: 入れたログから、その場で Claude に下書きを作らせます。ログを入れるたびに API を呼ぶので、環境変数 ANTHROPIC_API_KEY が要り、料金がかかります。

`run_advisor.py` は、`--run` を付けたときだけ API を呼びます(料金がかかります)。付けなければ呼びません。

ブラウザで `http://127.0.0.1:8765/` を開き、`data/synthetic/ryokan/before.ndjson` を落とします。
レポートの下に「直したあとのアクセス記録」の欄が出るので、`data/synthetic/ryokan/after.ndjson` を落とすと、前後の比較が出ます。
入れたログは、このパソコンの中で解析するだけです。画面(`serve.py`)は、ログをディスクに書き出さず、ファイルそのものを外に送ることもありません。
`--live` のときだけ、数えた結果(ブリーフ)を Claude に送ります。
テストは `python3 -m unittest discover -s tests` です。

## しくみ

1. コードがログを読み、AIの種類を分け(UAの表)、ページごとに数えます(`ashiato/`)。
2. 数えた結果と、サイトの情報から「ブリーフ」を作ります。Claudeに渡すのはこれだけで、生のログは渡しません。
3. Claudeが原因を判断し、下書きを書きます(指示は `prompts/advisor_ja.md`)。
4. 下書きはコードが検証します。根拠の行が無い、ブリーフに無い行を指す、事実と合わない種類(転送先が無いのに「転送」など)の下書きは、保存を拒否します。
5. 人が、承認・修正・却下します。サイトには何も書き込みません。

## 今の状況

**動くもの**
- ログの読み込み(Cloudflare Logpush、nginx/Apache)、AIの種類の判別、ページ別の集計、ブリーフの作成、下書きの検証、
  日本語の画面(ダッシュボード、調べた順番、次にやること、直したあとの変化)。
- 需要の読み取り: AIが取りに来て、無かったアドレス(404)と、よく読まれているページ(200)から、次に作るページの手がかりを読みます。
  404は、AIの推測のほか、古いリンクや消したページでも出るため、記録だけでは区別できません(前提と限界は `docs/design.md`)。
  提案には根拠が要り、根拠のない提案は保存を拒否します。AIが取りに来た回数は、AIが回答に使った回数ではありません。
- 下書きは Claude API(`claude-opus-5-5`)で取ります(`scripts/run_advisor.py`)。ブリーフと指示文だけを渡し、
  検証に落ちた下書きは理由を付けて出し直させます。API キーは環境変数から読み、`--run` を付けないと API を呼びません。Agent SDK は使っていません。

**確かめたこと**
- 画面の例(`examples/ryokan/`)は、Claude API から取った下書き9件です(検証: 有効9件、拒否0件)。
  合成データに仕込んだ7つの問題(`docs/design.md`)のすべてに対応していました(7つ目の偽装アクセスは「無視してよい」、
  「手を付けない」は1枚にまとまっている)。ほかに、よく読まれているページの「続きの話題」の提案が2件あります。
  1回の実行で、仕込んだ側が正解を知っている合成データでの結果です。実サイトでの正解率ではありません。
- 目2(サイトの公開ページの診断)は、合成データの旅館で、実際の API(`--live`。環境変数 ANTHROPIC_API_KEY が要り、料金がかかります)で
  1回動かしました。デモ動画では見せていません。
- Managed Agents(`agents/`、`environments/`、`scripts/run_advisor_managed.py`)は、合成データのブリーフで1回、実行しました
  (生ログは送っていません。下書き13件が、検証に1回で通りました)。そのあと指示文を変えたので、クラウドの Agent の指示文を、
  現行版に更新しました(`ant apply`)。更新後の指示文では、まだ実行していません。

**まだ確かめていないこと**
- 目3(AIの答え)は、偽のクライアントを使ったテストだけです。実際の API では、動かしていません。

**データについて**
- デモのデータは、すべて合成データです。直したあとのデータも、仮説にもとづいて作ったシナリオです(ChatGPT の利用が全体に増えるので、
  AIの要求は全体に約15%増える。提案したページ宛は、さらに上乗せされる。新しいURLの探索は続く。AIの回答から来た人も増える)。
  画面の数字は、この設定の結果で、実際の効果を示すものではありません。
- 実サイトでの確認は、集計の傾向を見たのみです。このリポジトリには、実際のログも、実際の集計値も入っていません。
- 画面の「見本」の下書きは、Claudeではなく決まった規則で作ったものです(Claudeの返答を渡さないと出ます)。
  `examples/readnote/` は、Claude Code の中の別のClaudeに、同じ条件で書かせた出力です。

設計とデモの台本は `docs/` にあります。
